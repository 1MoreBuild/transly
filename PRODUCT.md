# Product

## Register

product

## Users

People who read foreign-language articles in Chrome and care about translation quality, document context, and readable page layout. Many are comfortable supplying an API key but should not need to understand endpoint conventions, protocol variants, or model identifiers.

## Product Purpose

Transly turns web articles into coherent bilingual or translated reading experiences using an OpenAI-compatible model service chosen by the user. It owns extraction, translation orchestration, validation, caching, and page rendering while remaining independent from model hosting and authentication providers.

## Brand Personality

Clear, calm, and practical. Product language should be direct and human. The interface should feel focused and considered without looking technical for its own sake.

## Anti-references

Avoid dense all-in-one control panels, developer-first setup forms, hidden automatic behavior, decorative SaaS layouts, and product language tied to one model provider or local runtime. Do not make ordinary users understand implementation details before they can translate an article.

## Design Principles

1. Make the common path obvious and keep advanced controls available but quiet.
2. Prefer discovery and validated choices over asking users to type identifiers from memory.
3. Explain provider boundaries without making the provider the product identity.
4. Preserve the source page's visual hierarchy and keep translation controls unobtrusive.
5. Treat translation quality and reading continuity as the primary product requirements.

## Accessibility & Inclusion

Target WCAG 2.1 AA for extension-owned interfaces. Support keyboard navigation, visible focus, sufficient contrast, reduced motion, screen-reader labels, and status messages that do not rely on color alone.
